 rnote-mod_v1-5        2026-10-13
 STATUS: SOURCE READY - type-checked; settings schema validated and pie geometry rendered offline;
         NOT yet tried in the app
---------------------------------------------------------------------
 Pie menu polish (feedback on v1-4), saved opacity setting, and the program rename.

 PIE MENU
  - Slice numbers removed from the ring (the number keys 1-9 still pick a colour while the menu is open).
  - Centre circle (current colour) removed.
  - Slice corners are rounded (8 px).
  - The outline of the selected colour is drawn after all slices, so it overlaps both neighbours
    equally (in v1-4 the next slice painted over it, which looked lopsided).
  - Opacity: slices are 50% opaque by default. Configurable and SAVED: Settings panel -> new "Pie Menu"
    group (right below "General") -> "Pie Menu Opacity", 0.10 - 1.00. It is applied the next time the
    menu opens. The faint dimming of the page behind the menu is unchanged.

 PROGRAM RENAME (rnote.exe -> rnote-mod.exe)
  - The installed program is now bin\rnote-mod.exe. It is still BUILT as rnote.exe and only renamed
    when installing, so nothing inside the app depends on the file name.
  - Rnote-Mod is registered under its own Windows key (Applications\rnote-mod.exe) with the display
    name "Rnote-Mod" for the "Open with" list, so it no longer looks identical to the original Rnote.
    The original Rnote's registration is not touched.
  - Upgrading from v1-4 or earlier: the installer deletes the old bin\rnote.exe and re-creates the
    Start menu / desktop shortcuts. A taskbar pin that points at the old rnote.exe must be pinned again.
  - Anything that matched on the process name rnote.exe (old AutoHotkey rules) no longer matches the mod.

  4. crates/rnote-ui/data/app.gschema.xml.in      new saved setting pie-menu-opacity (default 0.5, range 0.1-1.0)

 FEATURE 6: palette colour cycling (standalone keybind).
   Shift+`  ->  next palette colour      (1 -> 2 -> ... -> 9 -> 1)
   Ctrl+`   ->  previous palette colour  (2 -> 1, 1 -> 9)
 - Independent of the pie menu and of whether the colour toolbar is used. It does
   exactly what clicking the palette colour does: the colour goes to the selected
   pad (stroke or fill) of the current pen.
 - Start point: the highlighted palette colour; if none is highlighted but the
   current colour equals a palette colour, it continues from that one; otherwise
   forward starts at colour 1 and backward at colour 9.
 - The key is accepted as grave or tilde (Shift turns one into the other).
 - Ignored while a dialog is open or a text field has focus. In the Text tool
   Shift+` is ignored (it types "~"); Ctrl+` still works there.

 FEATURE 2: colour pie menu (Space).
 - Space opens a ring of the nine palette colours centred on the pointer (moved
   inward near the window edges). Slice 1 is at the top, the rest follow clockwise;
   the slice numbers are drawn on it. The current colour has a white outline and is
   also shown in the middle.
 - Click / tap a slice: applies that palette colour (like clicking it in the
   toolbar) and closes the menu. The number keys 1-9 pick a slice too.
   Esc, Space again, or a click outside the ring closes it without a change.
   The page behind is dimmed slightly, and a click outside does not draw.
 - The slices always show the live palette, including colours you customised.
 - Text tool: Space still types a space (menu off). In the main window Space no
   longer activates a focused button (Enter still does).
 - While the menu is open, pressing Q/G/E/T switches tool and closes the menu.

 Changes:
  1. crates/rnote-ui/src/piemenu.rs                NEW  the pie menu (plain DrawingArea,
       drawn with cairo, added to the toolbar overlay so it covers the canvas area)
  2. crates/rnote-ui/src/appwindow/mod.rs
       Window-level key controller extended: colour cycling, Space / pie menu keys,
       pointer position tracking (motion controller on the toolbar overlay);

  3. crates/rnote-ui/src/colorpicker/mod.rs

 rnote-mod_v1-3        2026-10-12
 STATUS: BUILT on GitHub, installed and works (confirmed by user: Shape Cycling group, G cycling, saved list, Q presets)
---------------------------------------------------------------------
 FEATURE 5: shape cycling (G) and brush size preset cycling (Q).

 (a) Shaper - pressing the shaper shortcut again (G, or Ctrl+2) while the Shaper is
     already active switches to the next shape of YOUR cycle list:
       - Order follows the shape picker. After the last shape it wraps to the first.
       - If the current shape is not in the list, the first listed shape is used.
       - If the list is empty, nothing happens.
       - The first press from another tool only switches to the Shaper and keeps
         the last used shape, as before.
     The list is chosen in the Shaper configuration popover (the config button
     below the shape picker): a new "Shape Cycling" group at the bottom holds a
     collapsed row "Shapes in the cycle". Expand it for a scrollable list with
     one switch per shape (all 13). It is SAVED with the other settings (stored in
     the engine config JSON, so it survives restarts).
     Default list for a fresh/older config: Line, Arrow, Rectangle, Ellipse.
 (b) Brush - pressing the brush shortcut again (Q, or Ctrl+1) while the Brush is
     already active activates the next of the three stroke-width presets
     (1 -> 2 -> 3 -> 1). If no preset is highlighted, the first is used. This
     clicks the preset buttons; the +/- spin control is not touched. The size of a
     preset is still changed as before (select it, then adjust the width).

 Changes:
  1. crates/rnote-engine/src/pens/pensconfig/shaperconfig.rs
       New saved field cycle_builder_types (list of shapes, serde default, so old
       saved configs still load).
  2. crates/rnote-ui/src/penssidebar/shaperpage.rs
       cycle_shapebuildertype(); init_cycle_shapes_group() builds the settings
       group in code; refresh_ui() loads the switches from the saved list.
  3. crates/rnote-ui/src/strokewidthpicker/mod.rs
       cycle_setters(): next stroke-width preset with wrap-around.
  4. crates/rnote-ui/src/appwindow/actions.rs
       "pen-style" action: shaper / brush shortcut pressed while already active ->
       the cycle calls above (selector cycling from v1-1 unchanged).
  5. build-aux/rnote_inno.iss.in      version label -> v1-3
  6. .github/workflows/build-rnote-mod.yml   default build label -> v1-3
  7. rnote-mod_docs/                  changelog + project map v1-3

 Verification: whole workspace type-checks in the sandbox (UI, engine, CLI).
 NOT done: running the app. The new settings group is built in code, so its
 on-screen layout (popover height, scrolling) is untested.

 rnote-mod_v1-2        2026-10-11
 STATUS: BUILT on GitHub, installed and works (confirmed by user; pen/tablet parts not tested yet)
---------------------------------------------------------------------
 FEATURE 3: plain-key tool shortcuts.

   Q -> Brush (Ctrl+1)     G -> Shaper (Ctrl+2)
   E -> Eraser (Ctrl+4)    T -> Selector (Ctrl+5)
   Pressing T while the Selector is already active cycles its mode (Feature 1).
   The normal Ctrl+1..6 shortcuts are unchanged.

 A letter press is IGNORED (passes through to Rnote as before) when:
   - Ctrl, Shift, Super or Meta is held (Alt is allowed, so the shortcuts keep
     working while an Alt toggle from a pen button is active)
   - the Text tool is the current tool (the letters belong to the text input;
     leave the Text tool with Ctrl+1..6 or the toolbar)
   - a text field has keyboard focus (rename boxes, entries, ...)
   - a dialog is open
 It works wherever keyboard focus is inside the main window, including right
 after clicking a toolbar or colour button (the canvas itself only takes focus
 when it is pressed). Holding a key repeats it (holding T keeps cycling).

 Changes:
  1. crates/rnote-ui/src/appwindow/mod.rs
       setup_plain_key_shortcuts(): window-level key controller (capture phase),
       called from init(); handle_plain_key_tool_shortcut(): applies the rules
       above and switches tool through the existing "pen-style" action, the same
       path Ctrl+1..6 take.
  2. crates/rnote-ui/src/canvas/mod.rs
       text_preprocessing_enabled(): true while letters go to the text input.
  3. build-aux/rnote_inno.iss.in      version label -> v1-2
  4. .github/workflows/build-rnote-mod.yml   default build label -> v1-2
  5. rnote-mod_docs/                  changelog + project map v1-2

 Behaviour:
  While the Selector tool is active, pressing its shortcut again
  (Ctrl+5 or Ctrl+Numpad 5) switches to the next selector mode, in the
